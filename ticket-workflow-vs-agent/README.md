# 工单助手：固定流程、条件流程与 Agent 循环

原生 Node.js + Chat Completions 兼容接口。使用合成工单、本地只读工具；不读取真实订单，不连接业务系统，不执行删除、退款、支付或工单提交。

## 安装与运行

环境：Node.js 25.8.2、npm 11.9.0；无第三方运行依赖，支持 Node >=22。

```bash
npm ci
npm run verify
```

真实模型评估会消耗 API 配额。配置匹配同一供应商的凭据、模型及完整基础 URL；不要跨服务复用密钥。

```powershell
# OPENAI_API_KEY 通过本机环境配置，勿写入文件或提交。
$env:AI_EVAL_MODEL = '你的模型标识'
$env:AI_EVAL_BASE_URL = '你的兼容接口基础URL'
npm run eval:live
node summarize.mjs
```

未提供 AI_EVAL_BASE_URL 时使用 https://api.openai.com/v1；脚本不会自动读取 OPENAI_BASE_URL。未提供凭据或模型时退出 2，不会伪造结果。没有依赖安装也能运行，锁文件用于保持工程契约完整。

## 三种实现

- fixed：模型分类 → 查询订单 → 查询两类知识 → 模型生成终态。始终执行相同读取序列，缺失输入时工具返回 missing，不是假造 ID。
- conditional：模型分类 → 代码判断缺失/不支持 → 查询订单 → 代码判断失败 → 按 topics 查询知识 → 模型生成终态。明确的早退分支使用固定文案。
- agent：模型从 get_order / search_knowledge / finish 中选择下一步，工具结果反馈后继续。一次响应可以包含多个读取请求，执行器逐个执行；finish 必须单独返回。

工具、业务政策、任务集、temperature=0、模型与预算相同。工作流的模型只负责分类和最后归纳；Agent 同时看到工具清单并决定调用。这个结构差异本身会影响输入 Token。

固定流程是解释控制流差别的基线，不是优化充分的生产工作流。条件流程是更有参考价值的工程对照。没有为 Agent 人为强制每轮只调用一个工具；虽然请求设置 parallel_tool_calls=false，当前接入仍可能返回多个调用，执行器接纳并顺序执行。

共享工具层对临时订单查询失败最多重试一次。最多 6 次模型请求、8 条工具尝试预算、单次请求 45 秒、每个任务 180 秒。预算是应用规则，不由模型自行决定。样本里没有真实 I/O 延迟或退避等待，不宜据此评价真实后端恢复时延。

## 样本与评分

7 个样本：配送、支付、缺订单号、临时失败、复合事项、不支持、持续不可用。每个样本每种架构 2 次，共 42 次；第二轮反转架构顺序。

按预先定义的 status、adviceCodes、questionFields、reasonCode、evidenceIds 评分。resolved 必须同时提供真实取得的订单与知识证据。ask 与 handoff 可以是正确结果，不能包含处理建议。

这是窄范围结构化任务评分，不是完整语言质量评测；自动评分不判断文案语气、所有自然语言事实或多轮追问后的最终解决率。分类抽取错误可能传递到条件流程，代码分支不保证端到端正确。

报告保存终态、工具轨迹、每次请求 usage 和响应模型名，不保存凭据、基础 URL 或模型推理文本。工具尝试数包含内部失败重试；模型请求数包含分类/终态请求；两者不可混算。Token 总数来自服务返回的 total_tokens，不能直接换算账单金额，缓存命中与价格需另算。

## 本次记录与限制

请求与响应模型标识为 deepseek-flash，是本次接入返回的别名，不宣称不可变模型快照。使用 temperature=0 也不保证重复输出一致。累计输入包含多轮历史，部分请求命中供应商缓存；网络耗时也受接入服务波动影响。

本实验是已知业务路径的基线，没有用未知工具、隐藏知识或开放任务证明自主规划的上限。不能凭 7 个样本给出普遍成功率，也不能推断哪种架构永远更便宜。更广泛比较应增加未知路径、真实查询延迟、更多样本、多轮交互、人工文案评分与多模型验证。

接入预检曾遇到强制 tool_choice 不受当前思考模式支持、一次返回多个工具等兼容性问题；修正适配并统一证据规则后重新运行完整评估，最终报告只包含统一配置下的样本。

最终 42 次尝试中，41 次取得结构化结果并通过预定评分，1 次记录为 TypeError（未取得可评分结果，不推断为业务失败，也不确定底层原因）。使用 EVAL_RESUME=1 可跳过所有已记录尝试，包括错误，继续剩余任务，不覆盖失败记录。成本比较采用三组都完成的相同 13 个 case/trial 配对。

人工检查发现：fixed 和 agent 的部分 handoff 文案声称“已转交人工”，但本实验没有转交工具；部分支付建议还增加了知识库未提供的具体操作。不能把结构化通过当成完整答复正确。原始报告保留这些内容供审查。补充的 render.mjs 从已验证的结构化决定生成展示文案，不使用原始 message；它没有参与模型生成测量，不改变原始评分和调用次数。真实转交成功提示必须等待业务服务返回成功。
